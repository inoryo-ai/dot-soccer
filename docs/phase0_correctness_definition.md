## 1. このプロジェクトで「正しい結果」とは何か

MVPの目的は**2点を数字で検証する**こと（要件定義書 §6）。それ以外は範囲外。

- 正しい結果の例1: `npm run sim -- train --card running --times 20` を実行すると、
  **8回目でタイプが「バランス→ダイナモ」に変わる**。全7カードで3〜10回の範囲に収まる。
- 正しい結果の例2: 同じシードで2回実行すると、スコア・スタッツ・イベントログが
  **1件も違わずに一致**する（サーバー権威の試合処理・リプレイの土台になる）。
- 正しい結果の例3: プリセット6チームの総当たり3,000試合で、
  **全体勝率が70%を超えるチームが1つも無い**。かつ3チーム以上の間に
  「AはBに強く、BはCに強く、CはAに強い」というじゃんけん関係が実測で出る。
- 正しい結果の例4: 6チームの**能力合計が完全に一致**している（4,110）。
  差が出るのは特訓の内容（隠しパラメーター）だけ。

## 2. 「間違った結果」の具体例

- 間違いの例1: 特訓を20回繰り返してもタイプが変わらないカードがある
  → 「特訓で選手が変わる」という遊びの核が成立していない。
  （実際に発生した: マンツーマン単体／スペシャル4組。§12-#1 と D-10 で決着）
- 間違いの例2: 同じシードなのに結果が変わる（乱数のモジュール関数を使う、
  dict/set の反復順に依存する、並列実行で順序が混ざる）
  → 非同期PvPの不正検証・リプレイが不可能になる。
- 間違いの例3: 1チームが勝率90%になる／あるいは1チームが勝率10%になる
  → 「課金や時間だけでは勝てない」(GD-01/02) の検証が失敗している。
  **天井だけ見て床を見ないのも間違い**（弱すぎるプリセットを見逃す）。
- 間違いの例4: スタッツが現実離れしている（1試合で奪い合い4,000回、走行191km）
  → 数字を見たオーナーが仕様の妥当性を判断できない。
  （実際に発生した。1ティックごとに判断させていたのが原因）
- 間違いの例5: タイプを選手データに保存し、隠しパラメーターと食い違う。

## 4. ユーザーの行動想定

- ユーザーは誰か: **現時点ではオーナー自身**（MVPは画面なしのCLI）。
  将来の対象は「作戦を組むのが好きで、操作技術で勝ちたくない層」。
- 典型的な行動パターン: 定数を1つ変える → `batch` を回す → 勝率表を見る → また変える。
  この**反復の速さ**が価値なので、3,000試合が数分で終わることは要件の一部。
- 期待すること: 「特訓の違いが試合の動きと勝敗に出る」ことを、数字で納得できること。
- 絶対にやってほしくないこと: 検査が全部緑なのに、実は仕様を満たしていない状態で
  「完成しました」と報告されること。

## 5. 品質基準（定量）

| 指標 | 合格ライン | 測定方法 |
|------|----------|---------|
| タイプ変化回数 | 全7カードが3〜10回、かつ20回以内 | `npm run sim -- train-all` ／ 自動テスト |
| 再現性 | 同一シードでスコア・スタッツ・全イベントが一致 | 自動テスト（違うシードでは変わることも確認） |
| 試合の長さ | 常に 5,400 ティック | 自動テスト（5シード） |
| 上限 | 200回特訓しても能力・隠しが範囲外に出ない | 自動テスト（全7カード） |
| 能力合計 | 6チームで完全一致 | `npm run sim -- presets` ／ 検査スクリプト |
| 勝率 | 全体勝率が30%〜70%に収まる | `npm run sim -- batch --matches 200` |
| じゃんけん | 3チーム以上の循環関係が実測で存在 | 勝率表（対戦別） |
| バッチ所要時間 | 3,000試合が10分以内 | batch の実行時間表示 |

## 6. 前提条件

| 前提 | 崩れた場合の影響 | 代替策 |
|------|---------------|--------|
| 実行時に外部ライブラリを使わない（当初 Python 3.11 標準ライブラリのみ → 2026-10-02 に TypeScript へ移行・D-15） | — | 数値計算を自作で持つ（現状そうしている） |
| 1ティック＝1秒で十分な解像度 | 細かい駆け引きが表現できない | 0.2秒刻みにする（計算量5倍。並列で吸収） |
| 6プリセットで戦術相性を測れる | 相性の検証に偏りが出る | チーム数を増やす（`batch` は任意のチーム集合を取れる） |
| 勝率70%が「勝ちすぎ」の線 | 線がずれる | `src/sim/constants.ts` の1箇所で変更可能 |
| NFT・賭けはMVP範囲外 | — | 弁護士確認が済むまで実装しない |
