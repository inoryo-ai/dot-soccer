# ドットサッカー育成ゲーム（MVP）

**ブラウザで遊べます。** 試合は右斜め後ろからの見下ろしで、22人のドット絵が動きます。

```bash
npm ci                              # 開発ツール（TypeScript）を入れる。実行時に使う外部ライブラリは無い
npm run build:web                   # 配るものを web/dist に組み立てる
npx serve web/dist                  # などで配信 → http://localhost:3000
```

端末から遊ぶこともできます（Node.js 22.18 以上。`.ts` をそのまま実行します）。

```bash
npm run play
```

🔑 **試合の規則は `src/sim/` にしかありません。** ブラウザ版も端末版も同じ `src/sim/` を
動かしています。画面（`src/web/`）と端末（`src/cli/`）は規則を1行も持ちません。

🔑 **2026-10-02 に Python から TypeScript へ書き直しました**（決定 D-15）。
Python 版と**同じシードで同じ結果**になることを、Python 版が書き出した正解データと
1値ずつ照合して確かめています（`tests/golden/`）。詳しくは下の「TypeScript への書き直し」。

中身は3層になっている。

- **ゲーム層**（`play`）: 自チームを作り、8チームのリーグを14節戦い、試合で出た課題から
  特訓カードをもらって選手を育て、シーズンを越える。進行はセーブされる。
- **検証層**（`match` / `train` / `batch` / `scripts/measure.ts`）: ゲームの核を数字で確かめる道具。
  1. **特訓の違いで選手の隠しパラメーターとタイプが変わり、試合中の動きが変わること**
  2. **大量の自動対戦で勝ちすぎるチームがなく、戦術の相性（じゃんけん関係）が生まれること**
  3. **試合のスタッツが現実のサッカーの相場に収まっていること**（出典つき）
- **画面層**（`src/web/` と `web/index.html`）: ブラウザの画面。**規則は1行も持たない**。
  `src/web/api.ts` が返した値を並べるだけ。

- 要件定義書（**正本**）: `docs/requirements.md`
- 矛盾への決着の経緯（D-01〜D-17）: `docs/decisions.md`（決定の理由はこちら）
- 正しさの定義書: `docs/phase0_correctness_definition.md`

環境: **Node.js 22.18 以上 / TypeScript**。実行時に外部ライブラリを使わない（外部通信なし）。
🔑 `typescript`（型チェックとブラウザ用の JS 作成）だけが開発ツール。

## 遊び方（ゲーム層）

```bash
npm run play                                   # セーブがあれば続きから
npm run sim -- play --save saves/b.json        # 別のセーブで遊ぶ
```

### 1回の流れ

1. **チームを作る** — チーム名 / 運の種 / フォーメーション / **初期育成の配分**
   （全選手に特訓20回。AIチームも同じ20回を受けた状態で開幕するので、
   配分だけがチームの個性になる。プリセットと同じ配分を選ぶこともできる）
2. **戦術を決める** — ライン高さ・守備幅・姿勢・フォーメーション・
   チーム方針（条件→行動を最大5個）・監督の性格スライダー4つ
3. **試合へ** — 同じ節の他会場も同時に消化される。
   スコア・得点者・スタッツ・**課題から得た特訓カード**が表示される
4. **選手と特訓** — カードを1枚（通常）か2枚（スペシャル）使って選手を育てる。
   タイプが変わると表示される。先発と控えの入れ替えもここ
5. **14節終わったらシーズンを締める** — 最終順位が記録され、
   AIチームも自分の型で成長して次シーズンへ

### メニュー（端末版）

| | |
|---|---|
| 1 | 次の試合へ（全節終了後は「シーズンを締める」） |
| 2 | 選手と特訓（一覧・特訓・先発入れ替え） |
| 3 | 戦術を決める |
| 4 | 順位表と日程（残り日程・過去シーズンの成績） |
| 5 | セーブする（試合後・特訓後は自動セーブ） |
| 0 | セーブしてやめる |

リーグは **自チーム＋AI 7チーム = 8チーム、2回戦総当たりの14節**。
AIは要件定義書のプリセット6チーム＋リーグ用の「シュート型」。
セーブは端末版が `saves/default.json`（書き込みは別名に出してから置き換えるので、
途中で落ちても前のセーブは壊れない）、ブラウザ版がブラウザの localStorage（形は同じ）。

## 検証層の使い方

```bash
# チームJSONを作り直す（data/ に6プリセット + team_a / team_b）
npm run sim -- presets

# 1試合。スコア・スタッツ・課題を表示し、logs/ にJSONログを保存
npm run sim -- match data/team_a.json data/team_b.json --seed 1

# 特訓の検証。1回ごとの隠しパラメーターとタイプ、変化した回数
npm run sim -- train --card running --times 20
npm run sim -- train --card man_mark --card running --times 20   # 2枚＝スペシャル
npm run sim -- train-all --times 20                              # 全7カードの一覧

# 大量対戦（プリセット6チーム総当たり・各組200試合＝3,000試合）
npm run sim -- batch --matches 200 --seed 1
npm run sim -- batch --matches 20 --seed 1 --workers 4            # 軽く回すとき

# 検査
npm test                     # 自動テスト（235件・約30秒。3シーズン通しも含む）
npm run typecheck            # 型チェック
npm run check                # 提出前検査（ダミー値・定数の不変条件・実データ・配信物 ほか11項目）
npm run measure              # 平均スタッツの実測（数値が現実離れしていないか）
```

カード名: `running` / `man_mark` / `press` / `pass` / `dash` / `shoot` / `zone`

## TypeScript への書き直し（2026-10-02）

Python 3.11 で書いていたものを、規則・画面・コマンド・検査・テストまで全部 TypeScript に移した。

### 同じ結果になることの確かめ方

Python 版（コミット `8b126f0`）に正解データを書き出させ、TypeScript 版と1値ずつ照合している
（`tests/golden.test.ts` `tests/cli.test.ts`。作り方は `tests/golden/README.md`）。

| 照合したもの | 件数 |
|---|---|
| 乱数列（整数・文字列の種）／丸め・剰余・書式 | 9種 ／ 400件＋端数12件 |
| プリセット7チーム・自チームの初期編成 | 10チーム（全選手の能力・隠し・性質） |
| 特訓・タイプ判定・課題の判定 | 25回×11通り ／ 300件 ／ 200件 |
| 試合（イベント1件ずつ・スタッツ・課題） | 26試合（戦術・監督・方針を変えた試合を含む） |
| 再生用の座標 | 5,400コマ |
| 一括対戦の集計と表 | 30試合 |
| 2シーズン通しのキャリア（試合・カード・特訓・AIの成長・順位） | 28節＋シーズン締め2回 |
| コマンドの出力・対話画面を最後まで歩いた全記録とセーブ | 643行 |

`data/*.json` も TypeScript 版で作り直して**1バイトも変わらない**ことを確かめた。

### 書き直しで変わったこと（意図した変更）

- **D-16 数学関数を自前にした**: `Math.sin` などの最後のビットはブラウザごとに違い、
  Python の `math.sin` も OS ごとに違う（macOS では約15%が1ビット違った）。
  1ビットのずれが試合全体に伝わるので、四則演算だけで計算する `detmath.ts` にした。
  これで**どの OS・どのブラウザでも同じシードなら同じ試合**になる。
  そのかわり、macOS で動かしていた Python 版とは試合の細部が変わる（勝率表は下で測り直した）。
- **D-17 スタミナの数え間違いを直した**: Python 版は選手を `id()`（メモリの番地）で覚えていて、
  交代で番地が使い回されると「スタミナ20%未満になった選手」を少なく数えていた。
- **画面の特訓が止まる不具合を直した**: 特訓ボタンを押すと、Python 版の画面（`web/main.js`）は
  特訓の結果に**無い項目**（`visible` / `hidden`）を読もうとして例外になり、
  特訓はかかったのに画面が止まり、セーブもされなかった（公開版で再現を確認）。
  TypeScript の型の検査で見つかった。
- **Pyodide をやめた**: ブラウザで Python を動かすための約10MB の読み込みが無くなった
  （配信物は約260KB）。
- **速くなった**: 1試合 約94ms（同じMacの Python 版は約850ms）。

- ✅ **要件を満たす**: 全体勝率が30%〜70%の外に出るチームは**無い**（最高は堅守型の66.5%、最低はパス型の35.5%）

## 設計上の約束（崩さないこと）

| 約束 | 理由 |
|---|---|
| 乱数は `Match` の中の `PyRandom`（シード固定）だけで引く。`Math.random` は使わない | 種を渡せない乱数を使うとシード固定が破れる。テストで機械的に検出している |
| 試合の計算に `Math.sin/cos/atan2/exp/hypot` を使わない（`detmath.ts` / `pymath.ts` を使う） | 最後のビットが環境ごとに違い、同じシードでも試合が変わる（D-16）。テストで検出している |
| タイプは保存せず隠しパラメーターから導出する | 保存すると「同期を忘れる」故障が生まれる。JSONにタイプがあったら検査で落ちる |
| バッチのシードは `seedFor()` で導出する | 並列度・実行順が変わっても同じ試合には同じシードが渡る |
| `PRESS_STANDOFF_M > TACKLE_RADIUS_M` | 内側にすると全員が毎秒奪い合いに参加する（実測で1試合4,081回になった） |
| 1回の行動に秒数を持たせる（`ACTION_CONTROL_TICKS`） | 毎ティック判断させるとスタッツが現実離れする |
| run_space は相手最終ラインの**手前**まで | 越えるとオフサイドを免れて1試合6.6得点の壊れた強さになった |
| 勝率は床と天井の両方を警告する | 天井だけ見ると「弱すぎるプリセット」を見逃す |
| 自チームも必ず初期育成20回を受けてから開幕する | AIは20回育った状態。素で始めるとチーム合計で840点の差がつく（実測: 自3270 / AI4110） |
| 個性（能力の配分ずらし）は**特訓のあと**に付ける | 先に付けると +60 される能力が106になって上限で切られ、能力合計が減る |
| リーグは偶数チーム | 奇数だと必ず1チームが休みになり消化試合数が揃わない。検査で止めている |
| セーブは別名に書いてから置き換える | 書き込み中に落ちても前のセーブが残る |
| セーブの欠損・版違い・未知のカードは**エラーにする** | 既定値で埋めると壊れたデータのまま遊ばせることになる |
| `batch` のプリセットは6チームのまま | リーグ用に7チーム目を足したが、提出済みの勝率表の前提を変えない（検査で固定） |
| `src/sim/` からファイルや Node の機能を使わない（`src/node/` に分ける） | ブラウザでも同じ規則を動かすため。使うとブラウザ版が組み立てられなくなる |

## バランスについて（オーナー方針: 後から調整する）

実測は上の勝率表のとおり。**調整はすべて `src/sim/constants.ts` の1箇所**で行う。
ゲーム層を足しても `batch` の数字は変わらない（検査で固定している）ので、
定数を変えて `npm run sim -- batch --matches 20` を回せば、調整の効果をすぐ測れる（約7秒）。

🔴 定数を変えると `tests/golden.test.ts` `tests/cli.test.ts` の試合まわりの照合は当然一致しなくなる。
   それは意図した変化なので、理由を `docs/decisions.md` に書いてから
   `node scripts/gen_golden.ts` で作り直す（`tests/golden/README.md`）。

ゲーム層で新しく効くようになった調整つまみ:

| 定数 | 意味 |
|---|---|
| `AI_TRAININGS_PER_SEASON` | AIチームが1シーズンで選手1人に行う特訓回数（プレイヤーの成長速度との釣り合い） |
| `LEAGUE_DOUBLE_ROUND` | 2回戦総当たり（14節）か1回戦（7節）か |
| `MAX_CARD_STOCK` | 同じカードの所持上限 |

既知のバランス上の癖（未調整・要件の合格条件には触れない）:

- AIチームは**見える能力が既に上限100**に達しているので、シーズンを越えても伸びるのは
  隠しパラメーターだけ。プレイヤーは伸びしろが残っている能力を育てられるため、
  シーズンを重ねるとプレイヤー有利になっていく。
- じゃんけん関係が出ていない（上記）。
