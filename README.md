# ドットサッカー育成ゲーム（MVP）

**ブラウザで遊べます: https://dot-soccer.vercel.app**

街の施設を回ってチームを作り、8チームのリーグを戦いながら、特訓カードで選手を育てるサッカー育成ゲームです。
試合はブロックの3Dで描いています（スタジアム・ピッチ・選手はすべてコードで組んでいて、画像ファイルを持ち込んでいません）。

```bash
npm ci              # 開発ツール（TypeScript）を入れる。実行時に使う外部ライブラリは無い
npm run build:web   # 配るものを web/dist に組み立てる（TypeScript を変えたら毎回）
npm run dev         # 手元で配信 → http://localhost:4174/
```

端末から遊ぶこともできます（Node.js 22.18 以上。`.ts` をそのまま実行します）。

```bash
npm run play
```

🔑 **試合の規則は `src/sim/` にしかありません。** ブラウザ版も端末版も同じ `src/sim/` を
動かしています。画面（`src/web/`）と端末（`src/cli/`）は規則を1行も持ちません。

- 要件定義書（**正本**）: `docs/requirements.md`
- 決定の記録（D-01〜D-42）: `docs/decisions.md`（なぜそうしたかは全部こちら）
- 現実のサッカーの基準値と出典: `docs/realism-reference.md`
- 正しさの定義書: `docs/phase0_correctness_definition.md`

## 新しい試合エンジン（`src/sim/match/`・D-42）

### 考え方

- **物理を 0.1秒刻みで動かす。** ボールは空気抵抗（抗力危機）・転がり・弾みを持ち、浮き球やクロスは3次元で飛ぶ。
  選手の体は加速・減速・曲がれる速さに上限があり、疲れると最高速が下がる。値は論文・公式記録から取った
  （`docs/realism-reference.md`）。
- **結果をサイコロで決めない。** パスが通るか、シュートが入るかは「誰が先に触れるか」の物理で決まる。
  乱数は、蹴った瞬間のボールの向きと速さのブレ（技術・寄せられ具合で変わる）と、タックルで足が伸びる長さだけ。
- **AIは3層。** チームAI（陣形・役割を1秒ごと）→ 選手AI（持っている人の判断を0.2秒ごと）→ ステアリング（体を動かす）。
- **位置の価値は試合データから作った。** 「そこでボールを持つと、この先どれだけ点につながるか」（xT）を、
  Wyscout 公開データ 1,941試合から集計した（`src/sim/match/xt_grid.ts`・`scripts/build_xt.ts`）。
- **競技規則**: スローイン・ゴールキック・コーナーキック・オフサイド・ファウル・フリーキック・PK。
- **戦術のつまみ**（`src/sim/match/tactics.ts`）: プレスの開始位置・寄せる距離・奪い返し・ラインの高さ・陣形の大きさ・
  シュートコースを塞ぐ人数・ゴール前のマーク・パスで取るリスク・前へ急ぐ度合い・走り込む人数・撃つ見込みの閾値など。

### 現実と比べた数字（標準の型・1チームあたり）

| | 新エンジン | 現実 |
|---|---|---|
| シュート／実プレー1分 | 0.237 | 約0.23 |
| 得点／実プレー1分 | 0.028 | 約0.027 |
| エリア内から撃つ割合 | 66% | 56〜68% |
| 決定率（エリア内／外） | 15.9% ／ 4.1% | 13.6〜15.6% ／ 3.5〜4.2% |
| パス成功率 | 約80% | 78〜81% |
| 1人の走行距離 | 約10.6 km | 9.4〜11.2 km |
| スプリント回数 | 約16回 | 12〜22回 |
| 最後の15分の高強度の走り ÷ 最初の15分 | 0.63 | 0.55〜0.65 |

まだ現実と違う所: 枠内率が高い（44%・現実 約35%）、コーナーキックが少ない、実プレー時間が長い（63分・現実 54〜59分）、
**守備ラインを上げることに代償が無い**（裏を突かれない）。4すくみを作る前に、ここをエンジン側で直す（D-42 の最後）。

## 遊び方（ゲーム層・旧エンジン）

ブラウザ版は**街**から始まります。施設（サッカークラブ・商店街など）を選んで入り、チームを作って開幕します。
チーム作成は「左でチーム名・フォーメーション・運の種を決め、右の盤に選手を並べる」形です（D-38）。

端末版:

```bash
npm run play                                   # セーブがあれば続きから
npm run sim -- play --save saves/b.json        # 別のセーブで遊ぶ
```

### 1回の流れ

1. **チームを作る** — チーム名 / 運の種 / フォーメーション。
   端末版は**初期育成の配分**も選ぶ（全選手に特訓20回。AIチームも同じ20回を受けた状態で開幕する）。
   ブラウザ版は初期育成の配分を画面から外していて、全員が既定の配分で開幕する（D-38）
2. **戦術を決める** — ライン高さ・守備幅・姿勢・フォーメーション・
   チーム方針（条件→行動を最大5個）・監督の性格スライダー4つ
3. **試合へ** — 同じ節の他会場も同時に消化される。
   スコア・得点者・スタッツ・**課題から得た特訓カード**が表示される
4. **選手と特訓** — カードを1枚（通常）か2枚（スペシャル）使って選手を育てる。
   タイプが変わると表示される。先発と控えの入れ替えもここ
5. **14節終わったらシーズンを締める** — 最終順位が記録され、
   AIチームも自分の型で成長して次シーズンへ

リーグは **自チーム＋AI 7チーム = 8チーム、2回戦総当たりの14節**。
AIは要件定義書のプリセット6チーム＋リーグ用の「シュート型」。
セーブは端末版が `saves/default.json`（書き込みは別名に出してから置き換えるので、
途中で落ちても前のセーブは壊れない）、ブラウザ版がブラウザの localStorage（形は同じ）。
選手の顔は名前から導く（髪20 × 顔10 × 色5 = 1000通り・保存しない・D-37）。

### メニュー（端末版）

| | |
|---|---|
| 1 | 次の試合へ（全節終了後は「シーズンを締める」） |
| 2 | 選手と特訓（一覧・特訓・先発入れ替え） |
| 3 | 戦術を決める |
| 4 | 順位表と日程（残り日程・過去シーズンの成績） |
| 5 | セーブする（試合後・特訓後は自動セーブ） |
| 0 | セーブしてやめる |

## 設計上の約束（崩さないこと）

| 約束 | 理由 |
|---|---|
| 乱数はシード固定の `PyRandom` だけで引く。`Math.random` は使わない | 種を渡せない乱数を使うとシード固定が破れる。テストで機械的に検出している |
| 試合の計算に `Math.sin/cos/atan2/exp/hypot` を使わない（`detmath.ts` / `pymath.ts` を使う） | 最後のビットが環境ごとに違い、同じシードでも試合が変わる（D-16）。`src/sim/match/` も含めてテストで検出している |
| 新エンジンで乱数を引くのは `execution.ts` だけ。判断（AI）と先読みは乱数を使わない | 結果をサイコロで決めないため（D-42） |
| 新エンジンの値には出典を書く。出典の無い値は「設計値」と明記する | 合っているかを現実の数字と比べて確かめるため（`docs/realism-reference.md`） |
| タイプは保存せず隠しパラメーターから導出する | 保存すると「同期を忘れる」故障が生まれる。JSONにタイプがあったら検査で落ちる |
| 選手の顔は名前から導き、保存しない | 保存すると名前と顔がずれる（D-37） |
| バッチのシードは `seedFor()` で導出する | 並列度・実行順が変わっても同じ試合には同じシードが渡る |
| 勝率は床と天井の両方を警告する | 天井だけ見ると「弱すぎるプリセット」を見逃す |
| リーグは偶数チーム | 奇数だと必ず1チームが休みになり消化試合数が揃わない。検査で止めている |
| セーブは別名に書いてから置き換える | 書き込み中に落ちても前のセーブが残る |
| セーブの欠損・版違い・未知のカードは**エラーにする** | 既定値で埋めると壊れたデータのまま遊ばせることになる |
| `batch` のプリセットは6チームのまま | リーグ用に7チーム目を足したが、勝率表の前提を変えない（検査で固定） |
| `src/sim/` からファイルや Node の機能を使わない（`src/node/` に分ける） | ブラウザでも同じ規則を動かすため。使うとブラウザ版が組み立てられなくなる |
| 配るもの（`web/dist`）からコメントを落とす | 書いたコメントがそのまま公開される（2026-10-02 に取引先の名前が出かけた） |

## 旧エンジンのバランスについて

調整はすべて `src/sim/constants.ts` の1箇所で行う。
定数を変えて `npm run sim -- batch --matches 20` を回せば、調整の効果をすぐ測れる。

🔴 定数を変えると `tests/golden.test.ts` `tests/cli.test.ts` の試合まわりの照合は当然一致しなくなる。
   それは意図した変化なので、理由を `docs/decisions.md` に書いてから
   `node scripts/gen_golden.ts` で作り直す（`tests/golden/README.md`）。

既知のバランス上の癖:

- AIチームは**見える能力が既に上限100**に達しているので、シーズンを越えても伸びるのは
  隠しパラメーターだけ。シーズンを重ねるとプレイヤー有利になっていく（D-41 の未解決のテストもこれ）。
- じゃんけん関係が出ていない（上記）。

## データとライセンス

- 新エンジンの位置の価値（xT）は、**Wyscout 公開データ**（Pappalardo ら 2019, *Scientific Data*,
  https://doi.org/10.6084/m9.figshare.c.4415000.v5 ・**CC BY 4.0**）から集計した。
  元のデータはリポジトリに入れていない（集計した表 `src/sim/match/xt_grid.ts` だけ）。
- StatsBomb のオープンデータは利用規約で商用利用（派生した分析を含む）が禁じられているので使っていない。
- このリポジトリ自体のライセンスは**まだ決めていない**。

## MVPに含まれないもの

- **NFT・賭け要素**: 賭けで得たゲーム内通貨が外部取引可能なNFTにつながる構造は
  賭博罪の確認が必要（要件定義書 §12）。**弁護士確認まで実装しない。**
- **名称・キャラクター・UI のオリジナル化の判断**: 要件定義書 §12 に未決定として残っている。
- **非同期PvP・サーバー処理**（今はローカルのリーグ戦）。試合は決定論なので土台はできている
- `selection`（安定感↔期待感）スライダーの効果 — 要件定義書どおり値のみ保持
